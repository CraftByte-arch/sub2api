## Context

侧车使用主服务管理员 HTTP 接口。分组已有 is_exclusive；用户列表支持 group_name（模糊筛选授权分组）且返回 allowed_groups。主服务更新用户支持仅提交 allowed_groups，但它是全量替换而非原子追加。

## Goals / Non-Goals

Goals: 显示明确授予专属分组权限的用户；支持全选和跨页选择；只追加目标分组；分页界面、失败隔离、可重试。

Non-Goals: 不复制 API Key、余额、订阅、用户专属倍率；不查询使用记录/直接查询数据库；不改主服务；不定时同步；不部署。

## Decisions

- 新增独立 core/web 文件以及 group-access.js 模块，减少现有文件接入改动。
- GET /api/groups/{id}/access-users 支持可选 source_group_id。按需从主服务分页加载授权用户，以 group_name 缩小范围，必须再用 allowed_groups 的精确 ID 过滤，避免同名/相似名称误授权。不将倍率配置或 API Key 使用记录当作权限依据。最多扫描 10000 条；超限/任一页失败不返回不完整列表。列表不接入自动轮询，不持久缓存权限。
- POST /api/groups/{id}/access-users/sync 只接受 source_group_id 和明确 user_ids，每次 1–10 人。前端“同步全部”固定为确认时加载的用户快照，分批调用，不隐式纳入后来新增用户。已授权用户禁选。
- 写入前重新读取分组及每个用户，检查仍拥有来源分组权限；读取最新完整 allowed_groups 合并目标 ID。仅写 allowed_groups，验证主服务更新响应，分别返回 added/skipped/failed/unknown。同一客户端同步互斥，超时保留逐用户结果；结果未知不自动重试。
- 采用已有 teal/中性色、系统字体、8px 间距、圆角、modal-panel 和表格；标签打开宽弹窗，上方目标/来源/搜索，中间分页表，下方选择数量和主按钮。窄屏允许换行，不横向溢出。loading、空态、错误重试、二次确认、批次进度、关闭恢复焦点、滚动隔离。

## Risks / Trade-offs

- 主服务没有条件更新/原子追加接口 → 侧车串行、写前重读、仅写权限字段、写后核验，并提示不要同时在主后台修改同一用户。无法保证与主后台并发编辑绝对无冲突。
- HTTP 写入失败可能已生效 → 标记结果未确认，停止后续批次，提醒刷新核对；不自动重试。
- 主服务用户 API 有自身附加查询 → 仅点击时获取、按 group_name 缩小范围、关闭订阅附带查询、有界分页，无后台刷新。
- 禁用用户可拥有授权，但不代表可正常调用 → 单独显示用户状态；仅同步明确授权，不转移订阅权益。

## Migration Plan

无数据库迁移；后续经用户确认只部署侧车。回退侧车镜像不撤销已明确提交的用户授权。
