## Context

侧车总览已经按分组展示 API Key 账号，并通过管理员 HTTP API读取 Sub2API 的用量数据。Sub2API 的 `GET /api/v1/admin/dashboard/user-breakdown` 支持 `group_id`、日期范围、排序和数量限制，返回用户的请求数、Token 数、标准成本和实际扣费；本功能只需要在侧车按当前分组调用该接口并提供可读的弹窗。

## Goals / Non-Goals

**Goals:**

- 为每个真实分组提供当天实际扣费最高的前 20 位用户。
- 显示用户身份、今日实际消耗、请求数和 Token 数，并标明统计日期与查询时间。
- 让统计失败、无数据和部分字段缺失在弹窗中可理解、可重试。
- 复用现有管理员鉴权、设计系统和弹窗交互，不影响现有在线用户、账号调度和缓存命中率功能。

**Non-Goals:**

- 不修改 Sub2API 代码、数据库、计费口径或分组倍率。
- 不新增服务端持久化或长时间缓存；每次打开/刷新弹窗读取最新统计。
- 不为未归属真实分组的“未分组”合成视图请求 `group_id=0`。

## Decisions

### 1. 使用独立的分组统计接口

侧车新增受管理员鉴权保护的 `GET /api/groups/{groupID}/user-consumption`。服务端验证正数分组 ID，固定向 Sub2API 请求当天日期、`limit=20`、`sort_by=actual_cost`，避免浏览器控制返回规模或排序。

备选方案是复用 `/api/overview` 一次返回所有分组 Top 20，但这会让总览每 10 秒刷新都增加大量统计查询，并使一个分组统计故障影响整个页面；独立按需接口能隔离失败和负载。

### 2. 沿用实际扣费口径

返回字段使用 Sub2API `actual_cost`，与在线用户弹窗的 `today_actual_cost`保持一致。Token 使用 `total_tokens`，请求数使用 `requests`；缺失数值按不可用指针返回，不猜测或用 0 覆盖未知值。

### 3. 稳定排序与有限响应

服务端再次按实际消耗降序排序，并以 Token、请求数、用户 ID 作为并列时的稳定排序键。最多返回 20 行，响应体沿用侧车 JSON 上限；若上游返回异常字段，跳过无效用户 ID并将响应标记为 partial，同时保留可用行。

### 4. 弹窗状态与刷新

分组操作区新增“今日用户 Top 20”按钮。点击时记录触发按钮、打开全局弹窗并请求对应分组；弹窗包含加载骨架、空状态、错误重试和部分数据提示。打开弹窗期间沿用现有规则暂停后台轮询，关闭后恢复焦点。

### 5. 响应式与可访问性

桌面使用三列列表（用户、今日消耗、请求/Token），窄屏改为带字段标签的卡片布局。按钮使用明确的 `aria-haspopup`、`aria-controls` 和键盘可聚焦状态；未分组的合成分组不显示入口。

## Risks / Trade-offs

- [统计接口不可用或管理员权限不足] → 仅当前弹窗显示错误和重试，不影响总览、在线人数和账号调度。
- [某些版本只返回部分字段] → 保留用户行，金额/请求/Token 分别显示“暂不可用”，并标记 partial。
- [当天用户超过接口限制] → 服务端固定 `limit=20` 并显示“前 20 位”，不会误称为完整用户集合。
- [分组 ID 已删除或无效] → 返回明确的分组不存在/统计不可用错误，前端关闭或保留可重试状态。

## Migration Plan

仅更新侧车二进制或容器即可，无数据库迁移。回滚时只回滚侧车版本，Sub2API 主服务不受影响；本次不部署 HC2。

## Open Questions

- 后续若需要按标准成本或自定义日期范围，可在不改变当前接口兼容性的前提下增加独立参数。
