## Context

`account-auto-scheduler` 已经支持按“分组-账号”保存倍率保护关系，并在最终倍率超过阈值时解除 Sub2API 的物理绑定。当前阈值存储在每条账号关系上，因此同一分组下的多个 API Key 需要重复配置。实现必须继续只改侧车服务：Sub2API 的账号绑定接口和计费字段保持不变，旧状态文件与没有保护配置的账号继续按原逻辑运行。

## Goals / Non-Goals

**Goals:**

- 为每个分组保存一个可选默认保护倍率，并通过管理员鉴权 API/页面维护。
- 计算有效保护倍率时使用“账号级显式值 > 分组级默认值”的优先级。
- 让继承分组默认值的关系与账号级保护使用同一套安全状态机：超过阈值自动解绑、恢复后自动回绑、物理解绑后仍保留逻辑成员。
- 当最终倍率不存在、无效、过期或无法唯一匹配上游 Key 时保持当前物理状态，不作解绑或回绑决定。
- 保留管理员手动移除的语义：移除后清除该关系的账号级/派生保护意图，后续分组默认值不会把它重新绑定。
- 在 overview 和分组绑定弹窗中展示分组默认值、实际生效阈值及来源。

**Non-Goals:**

- 不修改 Sub2API 源码、数据库、`rate_multiplier`、账号余额或调度状态。
- 不为没有物理绑定、没有既有逻辑保护记录的账号凭空创建分组成员关系。
- 不改变严格“超过”才触发保护的边界：最终倍率等于阈值时保持/恢复绑定。
- 不新增上游请求；继续使用侧车已同步的最终倍率快照。

## Decisions

### 1. 分离保存分组默认值与账号关系

在 `model.State` 增加可选的 `GroupProtectionDefaults` 映射，键为分组 ID，值包含阈值和时间戳；在 `store` 增加独立的 `GroupProtectionDefaultStore` 接口。这样分组配置不会与现有 `Protections` 中的账号关系混淆，旧状态文件缺失该字段时自动初始化为空映射。

### 2. 账号级记录显式标识来源

给现有 `GroupAccountProtection` 增加来源字段（旧值为空时按账号级处理）。分组默认值触发解绑时创建带 `Scope=group` 的派生关系，记录上游/身份/Key 来源和当前状态；账号级记录永远覆盖分组默认值。派生关系仅用于已经物理绑定或已有逻辑关系的账号，避免管理员手动移除的账号被默认规则重新加入。

### 3. 统一有效阈值解析

保护协调器为每个 `(groupID, accountID)` 先读取账号级记录；不存在时再读取分组默认值。账号级记录存在但阈值无效时报告不可用，不回退到分组值，防止管理员的显式配置被静默绕过。没有任何有效阈值时走现有未保护逻辑。

### 4. 在现有协调点运行分组规则

复用启动、周期同步、最终倍率刷新、绑定变更后的保护协调入口。每轮只处理：物理绑定账号，或已经存在的账号级/分组派生逻辑关系。超过阈值时先解除物理绑定并保留派生记录；恢复到阈值以内时先绑定成功再清理派生记录。分组默认值被删除时清理所有派生记录并恢复仍有逻辑意图的关系。

### 5. 扩展投影而不是复制账号数据

overview 继续返回原始 Sub2API 分组/账号，侧车额外返回 `group_protection_defaults` 和包含来源的 `group_protections`。保护视图增加 `scope`/`inherited` 字段；前端在分组标题编辑默认值，在账号行显示当前实际阈值及“账号级/分组默认”来源。最终倍率为空时显示“不生效”，但不允许前端据此发起自动绑定。

### 6. 管理员 API 保持资源化和鉴权一致

新增 `GET/PUT/DELETE /api/groups/{groupID}/protection-default`，沿用现有管理员中间件与数值校验。账号级设置、解除和移除接口保持现有路径不变；删除分组默认值是幂等操作，写入无效值在请求层拒绝。

## Risks / Trade-offs

- [同一分组下账号级保护与分组默认值同时存在] → 有账号级记录就完全跳过分组默认逻辑，并在视图中明确显示账号级来源。
- [分组默认值触发时账号绑定已被管理员手动移除] → 仅对物理绑定或已有逻辑记录的账号生成/维护派生记录；未绑定且无记录的账号永不自动绑定。
- [最终倍率暂不可用] → 保留上一轮物理状态，状态显示不可用原因；不猜测阈值结果。
- [自动解绑或回绑的 Sub2API 请求失败] → 保留派生/账号级记录和错误信息，下一轮继续重试；不会删除逻辑成员意图。
- [旧状态文件无新字段] → 读取时初始化空映射，版本兼容逻辑与现有保护记录保持不变。

## Migration Plan

1. 侧车启动时接受旧状态版本并把缺失的分组默认值初始化为空。
2. 管理员先在分组标题配置默认值，再观察账号行显示的继承来源和自动状态。
3. 验证账号级覆盖、最终倍率不可用不动作、超过阈值解绑、恢复回绑和手动移除不回绑。
4. 回滚时删除/停用侧车新版本即可；Sub2API 不需要迁移，旧侧车会忽略新增状态字段。

## Open Questions

无。阈值比较沿用现有严格“超过”语义，等于保护倍率视为安全。
