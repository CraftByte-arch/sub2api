## Why

当前倍率保护只能逐个配置“分组-账号”关系；当一个分组包含多个 API Key 账号时，管理员需要重复录入相同阈值，维护成本高且容易漏配。需要在分组层提供默认保护倍率，同时保留账号级配置的覆盖能力，并确保没有最终倍率时不会误解绑或误回绑账号。

## What Changes

- 为分组增加可选的默认倍率保护设置，并提供管理员后台的设置、修改和清除操作。
- 账号级保护倍率优先于分组级默认值；只有账号级未设置时才继承分组级默认值。
- 继承分组保护的账号在最终倍率严格超过阈值时自动解除实际分组绑定，倍率恢复到阈值以内时自动回绑，并在侧车中保留逻辑成员状态。
- 最终倍率缺失、无效或无法确定时，分组保护不触发任何解绑或回绑。
- 账号被管理员手动移除后，不因分组默认保护重新绑定；账号级保护和既有手动操作语义保持不变。
- 在分组和账号列表中显示分组默认保护、账号实际生效的保护来源与阈值。
- 保持未配置任何保护倍率的分组和账号完全走原有逻辑，不修改 Sub2API 代码、计费倍率或数据库结构。

## Capabilities

### New Capabilities

- `group-level-rate-protection`: 分组默认倍率保护、账号级覆盖、自动解绑/回绑和无最终倍率时的安全语义。

### Modified Capabilities

无。分组级能力会在侧车现有账号级保护之上增加默认值继承规则，不改变已有账号级保护接口的契约。

## Impact

- 影响 `account-auto-scheduler` 的状态模型、持久化、保护协调器、管理员 API、overview 投影和分组/账号管理界面。
- 复用现有管理员鉴权、账号分组绑定接口和最终倍率同步结果；不新增上游网络调用。
- 旧侧车状态文件继续兼容，未配置保护的现有关系无需迁移；Sub2API 单独运行时不读取这些可选字段，因此原有逻辑不受影响。
