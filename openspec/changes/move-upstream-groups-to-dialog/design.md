## Context

上游分组快照属于登录身份，当前界面在每个展开身份下直接渲染完整候选集合。一个上游包含多个身份和许多候选分组时，列表高度会显著增长；管理员仍需要查看完整候选集合，并核对其中哪些分组已经有远端 Key 绑定到本地 API Key。

现有上游管理响应已经包含身份分组快照、远端 Key 的 `group` 与 `local_account_id`、本地账号列表，以及分组最终倍率；本变更不需要新的服务端投影。

## Goals / Non-Goals

**Goals:**

- 让上游主行保持紧凑，仅显示一个上游分组按钮和准确数量。
- 以原生模态框呈现全部可用分组的身份、分组、平台类型、倍率、远端 Key 和本地 API Key 账号；未绑定项也保留。
- 保留无法关联完整快照的已绑定 Key，避免遗漏管理员实际使用的分组。
- 遵循已有弹窗的关闭、取消和焦点恢复行为，并在窄屏下改为标签式单列信息。

**Non-Goals:**

- 不新增服务端接口、上游同步或数据持久化字段。
- 不在该弹窗内修改绑定关系、分组倍率或账号调度。
- 不根据名称推断未知平台类型。

## Decisions

### 浏览器基于已有快照投影分组及绑定关系

弹窗以登录身份为边界，先投影 `identity.groups` 中的全部可用分组。再将存在 `local_account_id` 的远端 Key 以分组 ID 精确匹配、其次以名称匹配挂到对应分组；没有绑定的分组仍输出“未绑定本地 API Key”。找不到匹配快照的绑定 Key 创建仅包含 Key 分组名称的推断行，并明确显示“快照未匹配”。

替代方案是在后端返回专用绑定分组 API。该方案会重复已有数据、扩大接口与测试范围，且不提升当前管理员查看场景的性能，因此不采用。

### 主列表采用渐进披露

移除身份详情中的完整可用分组表。每个上游行增加带数量的“上游分组”按钮，管理员只在点击后浏览完整分组集合及绑定关系。资源摘要仍可保留全部可用分组的数量。

### 只读原生对话框

使用与既有上游充值、绑定管理一致的 `<dialog>` 模式。打开时设置上游标题及内容，关闭或 Escape 时恢复到触发按钮；对话框无需网络加载，所以不显示忙碌状态。

## Risks / Trade-offs

- [远端 Key 的分组名称与快照 ID 不同] → 先匹配 ID、再匹配名称，并保留不匹配的推断行。
- [一个分组有多个已绑定 Key] → 汇总为一行，完整显示对应远端 Key 与本地账号列表。
- [旧服务端尚未返回分组快照] → 弹窗仍从已绑定 Key 推断分组，并提示快照未匹配；没有分组快照且没有绑定时显示明确空状态。
- [窄屏表格信息拥挤] → 复用移动端字段标签，将每行折叠为单列而非水平滚动。

## Migration Plan

1. 发布仅更新侧车静态页面；已有 API 响应无需迁移。
2. 回滚只需替换侧车镜像；不影响状态文件、上游会话或 Sub2API 主服务。
