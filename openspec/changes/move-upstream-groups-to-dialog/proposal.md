## Why

上游可用分组按登录身份直接平铺在展开区域，会把上游管理列表拉得很长；管理员需要保留查看全部候选分组的能力，同时快速辨认哪些分组的上游 Key 已绑定到本地 API Key。

## What Changes

- 将上游详情中的完整可用分组表移出主列表，在每个上游行提供“上游分组”按钮和数量。
- 点击按钮后打开弹窗，按登录身份展示全部可用分组、平台类型、分组倍率、最终倍率，以及该分组内已绑定的上游 Key 与本地 API Key 账号。
- 未绑定分组明确显示“未绑定本地 API Key”；对无法匹配完整可用分组快照但已有绑定的 Key，仍显示推断出的分组行并标明快照信息不足。

## Capabilities

### New Capabilities

- `upstream-bound-group-dialog`: 在侧车上游管理中以弹窗查看每个上游全部可用分组、其倍率信息及本地 API Key 绑定关系。

### Modified Capabilities

- 无。

## Impact

- 仅修改 `account-auto-scheduler` 的上游管理静态界面、已有弹窗交互和相关前端测试。
- 复用已有的上游身份、分组快照与远端 Key 绑定数据，不增加 API、数据库或上游请求。
