## Context

上游侧车已经能够根据管理员配置的充值倍率和已绑定上游 Key 的分组倍率计算最终成本倍率。Sub2API 当前的 `accounts.rate_multiplier` 参与账号成本、配额和用量统计，不能复用；现有 OpenAI 上游成本排序则读取探测快照中的倍率。需要在不改变计费字段、不增加数据库迁移的情况下，把最终成本作为可选的调度信号。

## Goals / Non-Goals

**Goals:**

- 将最终成本倍率持久化为 `accounts.extra.final_cost_multiplier`，作为独立、可选的调度字段。
- 侧车在绑定、上游同步、充值倍率变更和周期同步后更新该字段；无法可靠计算时清空该字段。
- OpenAI 成本排序和利润准入优先使用有效的最终成本倍率；字段缺失、无效或旧账号没有该字段时完整回退现有逻辑。
- 保持 `accounts.rate_multiplier`、用户分组收费、账号配额计费和历史用量日志语义不变。
- Sub2API 在没有侧车或没有任何账号携带该字段时保持完整的历史行为，不引入额外依赖或远程调用。

**Non-Goals:**

- 不新增数据库列，不改变既有账号计费倍率。
- 不把探测倍率改写为最终成本倍率。
- 不改变 OAuth 账号的现有调度逻辑；即使 Extra 中意外出现同名字段也不采用。
- 不为非 OpenAI 平台新增全新的成本排序算法。

## Decisions

### 1. 使用现有 `extra` JSONB 存储字段

将字段命名为 `final_cost_multiplier`，写入账号 `extra` JSONB。侧车复用现有管理员 `POST /api/v1/admin/accounts/bulk-update` 接口；该路径对 Extra 执行数据库级 JSONB 顶层键合并并触发调度 outbox，不会覆盖其它 Extra 配置。调度快照也会携带 Extra，因此不需要新增路由、数据库迁移、Ent 生成代码或计费表改动。字段值必须是有限且大于等于 0 的数字；`0` 是有效值。

备选方案是新增 `accounts` 表列，语义更清晰但需要迁移、Ent schema、查询投影和回滚处理，不符合本次最小改动目标。

### 2. 侧车作为最终倍率的写入方

侧车只对 API Key 账号写入该字段。只有存在唯一有效绑定、充值倍率和上游 Key 倍率时才写入数值；未绑定、绑定歧义、倍率缺失或无效时写入 `null`，从而触发主服务回退。更新通过现有管理员批量更新接口完成，请求体只包含账号 ID 和 `extra.final_cost_multiplier`，不发送 `rate_multiplier`。

### 3. 调度读取采用“最终倍率优先、原逻辑兜底”

- OpenAI API Key 成本排序：有效 `final_cost_multiplier` 优先；否则读取现有新鲜探测倍率。
- 利润门和利润预演：有效最终倍率优先；否则继续使用 `accounts.rate_multiplier`，包括原有非法/缺失值处理。
- 其它调度因子、负载、优先级、粘性和计费流程不变。

这样老账号和未配置账号的行为保持原样，新字段只在明确设置时生效。

### 4. 通过独立数值信号避免口径分裂和计费污染

在独立 service 文件中提供不可导出的调度成本信号解析 helper，调度器、利润门和预演共用同一套有限数值校验。helper 只返回倍率数值、有效性和来源，不复制、不修改、不返回伪装过 `RateMultiplier` 的 `Account` 对象。计费路径继续直接读取原账号的 `accounts.rate_multiplier`，从类型和数据流上隔离调度成本与计费倍率。

原有代码只保留三个显式接入点：OpenAI API Key 成本排序、利润准入和利润预演。字段缺失或无效时，helper 返回未命中，调用方执行原有分支，因此没有侧车时不会引入任何行为变化。

## Risks / Trade-offs

- [字段写入失败] → 侧车记录同步错误并保留旧值；如果明确清除失败，不主动改变主服务原有行为。
- [最终倍率过期] → 侧车在绑定、充值倍率、Key 同步和周期任务后重新计算；主服务只在字段存在时使用，运维可通过清空字段立即回退。
- [多个身份或绑定导致成本不明确] → 侧车不写数值而是清空字段，避免错误地把一个账号当成错误成本。
- [调度快照短暂滞后] → 复用现有 Extra 更新触发的调度 outbox/快照刷新机制；即使刷新延迟，旧值只在短窗口内生效。
- [探测倍率与最终倍率同时存在] → 两者保留独立字段，UI 和日志继续展示探测结果，调度明确记录最终倍率优先的语义。
- [未来代码误把调度成本用于计费] → helper 不返回账号副本、不修改 `RateMultiplier`，并通过回归测试证明设置最终倍率不会改变计费结果。

## Migration Plan

无需数据库迁移。仅部署 Sub2API 时没有写入方，所有账号继续沿用旧逻辑。部署侧车后，首次周期同步会为可计算的已绑定 API Key 写入字段；未写入的账号仍沿用旧逻辑。回滚时停止侧车写入并通过现有批量更新接口将该字段设为 `null`，主服务在正常缓存刷新后恢复原有调度/利润逻辑。
