## Context

侧车已经通过 `ConsoleCore` 调用 Sub2API 的管理员接口，并且 `/api/overview` 由管理员会话保护。Sub2API 已提供管理员请求明细接口 `/api/v1/admin/ops/requests`，可按精确 RFC3339 时间范围返回成功和失败请求的用户 ID、调用时间等字段；同时提供 `/api/v1/admin/dashboard/users-usage`，可批量返回用户的今日实际消耗。侧车不应直接连接 Sub2API 数据库，也不应为了该功能修改主服务。

## Goals / Non-Goals

**Goals:**

- 在侧车总览显示最近 10 分钟内有请求的去重用户数。
- 在每个分组标题显示同一窗口内按“用户 + 分组”去重的在线人数，同时保留全站去重人数。
- 管理员点击指标后可查看所有在线用户的身份、最后调用时间、今日实际消耗金额和 token 数。
- 成功请求和已被 Ops 记录的失败请求都能使用户进入在线集合。
- 在线查询失败时总览仍可用，并提供明确的不可用状态。
- 限制远程请求的页数、并发和响应大小，避免在线指标拖垮管理接口。

**Non-Goals:**

- 不修改 Sub2API 代码、数据库、缓存或计费逻辑。
- 不记录新的用户活动数据；在线状态只基于现有请求/用量记录即时计算。
- 不把在线用户指标用于账号调度、计费或告警。

## Decisions

### 1. 使用独立在线用户接口，不阻塞既有总览

侧车新增受管理员鉴权保护的 `GET /api/online-users`。总览页在加载 `/api/overview` 后并行/随后请求该接口，在线接口失败只影响在线卡片和弹窗，不影响分组与账号数据。点击卡片时再次刷新在线用户列表，确保弹窗数据是新鲜的。

### 2. 用 Ops 请求明细作为十分钟窗口来源

客户端以当前 UTC 时间构造 `[now-10m, now)` 的 `start_time`/`end_time`，调用 `/admin/ops/requests`，`kind=all`、按 `created_at_desc` 分页读取，直到遍历完窗口内记录或达到安全上限。按正数 `user_id` 去重并保留每个用户最新 `created_at`；同时为每个用户保留窗口内出现过的 `group_id` 集合，因此同一用户在同一分组只计一次，在不同分组则分别计入。当前 Ops DTO 对未分组请求省略 `group_id`，侧车按当前接口契约将其归入合成分组 `0`。这样不依赖把日期范围近似成整天，也能覆盖已记录的失败请求。

如果 Ops 请求明细接口因未启用监控、旧版本或权限返回 404/405/功能未启用错误，客户端降级调用 `/admin/usage` 的当天分页接口，按记录的 `created_at` 在侧车过滤最近十分钟；降级来源只包含用量日志中的请求，仍能提供成功调用的在线用户。

### 3. 批量补齐身份与今日消耗

Ops 明细只携带用户 ID，因此侧车对去重后的用户 ID 分批调用 `/admin/users/{id}` 获取用户名/邮箱，然后调用 `/admin/dashboard/users-usage` 一次批量获取今日 `today_actual_cost` 与 token 字段。用户详情读取采用有限并发；单个用户读取失败时保留 ID 并以脱敏的“用户 #ID”显示，不让一个用户阻断整个列表。

### 4. 数据模型和口径

侧车返回 `window_minutes=10`、全站 `count`、`group_counts`、`group_counts_available`、`group_counts_partial`、`users` 和 `queried_at`。`group_counts` 的键为请求时的分组 ID，值为该分组去重用户数；缺少键且分组数据完整时表示明确的零。每行包含 `id`、`display_name`、`email`、`last_call_at`、`today_cost`、`today_tokens`。金额使用 Sub2API 的 `today_actual_cost`（用户实际扣费口径），token 为输入、输出及缓存 token 总和；若上游版本只返回部分字段，缺失值按不可用处理而不是猜测。

### 5. 前端交互

在现有指标带增加可点击的“在线使用”指标，显示全站人数和“最近 10 分钟”说明。每个分组的统计区域增加紧凑的“在线 N”徽标：完整数据使用成功色，可能低估使用警告色，暂不可用使用中性色，并始终保留文字和可访问标签，不只依赖颜色。按钮具备键盘焦点、`aria-haspopup=dialog` 和禁用/加载态。弹窗使用现有 `<dialog>` 体系，提供加载、空列表、错误重试和表格/移动端卡片布局；时间显示使用浏览器本地化格式，金额保留 4 位有效小数以适配小额用量。

### 6. 缓存与刷新

侧车不做长时间服务端缓存；同一请求内复用用户详情和批量消耗结果。页面现有 10 秒轮询更新在线人数，弹窗打开时暂停后台轮询（沿用现有 dialog 规则），关闭后下次轮询继续。在线接口设置较短的请求超时，避免影响页面响应。

## Risks / Trade-offs

- [Ops 监控关闭或旧版无明细接口] → 使用当天 `/admin/usage` 降级；UI 标注数据来源/可能只覆盖成功用量记录。
- [十分钟内请求量很大] → Ops 分页最多读取受控页数，按时间排序提前停止；超过上限时返回 `truncated=true` 并在弹窗显示“结果已截断”。
- [分组字段缺失或使用成功用量降级] → 返回 `group_counts_partial` 或 `group_counts_available=false`；分组徽标显示警告或不可用，不把未知值伪装成完整零。
- [用户已删除或单用户详情无权限] → 保留正数 ID，用“用户 #ID”脱敏显示，今日消耗仍可展示。
- [批量用户统计接口失败] → 在线人数和最后调用时间仍返回，今日消耗显示“暂不可用”，并允许点击重试。
- [不同版本返回字段差异] → 使用宽松 JSON 解码和字段别名，未知/缺失字段按零或空值处理，不影响其他数据。

## Migration Plan

1. 仅部署侧车新镜像/二进制；不执行 Sub2API 数据库迁移。
2. 先验证 `/api/online-users` 的管理员鉴权、超时和降级路径，再打开前端指标。
3. 若异常，回滚侧车镜像即可，Sub2API 主服务和既有账号调度逻辑不受影响。

## Open Questions

- 当前主服务是否始终启用 Ops 监控；实现会保留降级路径，因此不阻塞上线。
- “今日消耗”默认展示实际扣费金额；若后续需要标准成本，可在不改变在线判定的情况下新增字段。
