## Why

管理员目前只能通过自动检测策略间接改变 API Key 账号的调度状态，无法在侧车的分组账号列表中直接手动停止或启用账号。新增独立的全局调度控制后，管理员可以在不进入 Sub2API 原后台、也不修改主服务代码的情况下立即干预账号调度。

## What Changes

- 在侧车新增受管理员会话保护的账号调度接口，通过现有 Sub2API 管理 HTTP 接口修改 API Key 账号的 `schedulable` 状态。
- 为侧车引擎增加手动停止/启用语义和检测并发保护，区分管理员手动停止与状态检测自动停止。
- 在“分组与账号”页面的 API Key 账号行新增“账号调度（全局）”开关，显示保存中、检测运行中、非活动账号等禁用状态。
- 手动停止前进行二次确认；手动恢复检测自动暂停的账号时说明自动检测规则仍可能再次暂停该账号。
- 保持账号检测配置和历史记录；管理员手动停止后检测仍继续，但健康结果不会自动恢复该账号。

## Capabilities

### New Capabilities

- `sidecar-manual-account-scheduling`: 管理员通过侧车手动控制 API Key 账号的全局调度资格，并与自动检测状态机安全协作。

### Modified Capabilities

无。

## Impact

- 侧车引擎、管理员 HTTP API、分组账号列表前端和相关测试会发生变化。
- Sub2API 主服务代码和数据库结构不变；侧车复用现有 `/admin/accounts/{id}/schedulable` 管理接口。
- 手动切换作用于账号全局调度资格，因此该账号所在的所有分组都会受到影响。
