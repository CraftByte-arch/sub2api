## Context

“管理分组账号”弹窗当前由 `app.js` 的 `renderBindingList` 从 `/api/overview` 返回的 `accounts` 集合渲染。每个账号对象已经带有 `upstream_final_multiplier` 和 `admin_balance`：前者是侧车根据绑定上游 Key、充值倍率和分组倍率计算出的最终倍率，后者包含管理员余额投影及余额不足/不限等状态。绑定接口和分组兼容性判断已经独立工作。

本变更只改善侧车管理弹窗的信息呈现，要求不触发额外上游请求、不修改 Sub2API，也不改变复选框绑定提交协议。

## Goals / Non-Goals

**Goals:**

- 在每个绑定候选账号行中展示最终倍率和可用余额。
- 明确展示“未计算”“暂不可用”“余额不足”“不限”等不可用状态，并通过 `title` 提供原因或数据来源。
- 复用现有格式化函数、语义颜色和数据密集型表格风格。
- 桌面端保持列式对齐，小屏端改为带字段标签的堆叠信息，避免横向溢出。

**Non-Goals:**

- 不增加新的后端端点或新的上游同步任务。
- 不改变账号绑定、平台兼容筛选、搜索、批量保存或排序逻辑。
- 不把管理员余额展示值写回 Sub2API，也不改变账号计费。

## Decisions

1. **数据来源使用现有 overview 投影。**
   - 最终倍率读取 `account.upstream_final_multiplier`，余额读取 `account.admin_balance` 中的 managed balance projection；这样与分组账号主列表的管理员余额显示保持一致，并避免弹窗打开时产生网络请求。
   - 对 `managed === false` 且没有可用的剩余值的账号显示“暂不可用”，而不是把未配置额度误当成 0。

2. **以独立的指标列呈现，而不是拼接到账号名称。**
   - 绑定行增加“最终倍率”和“可用余额”两个单元格，分别使用 tabular numeric 字体和语义色。
   - 倍率可用时显示 `0.16x`，同时在悬浮说明中保留充值倍率 × 分组倍率的来源；状态异常时显示状态文本及原因。
   - 余额有数值时沿用 `formatCurrency`；不限、余额不足、未同步等状态显示文字，余额不足使用 danger 语义并附 `aria-label`/`title`。

3. **保持绑定状态信息独立。**
   - 现有“调度状态”和“分组归属”列保留，不用颜色替代文字，也不让新增指标影响 checkbox 状态或 `bindingChanges` 计算。

4. **响应式采用 CSS 网格降级。**
   - 桌面端扩展 `binding-row` 网格列；小屏端把指标列放到账号信息下方，并显示字段标签，隐藏次要分组数量信息，复用现有 620px 断点。

## Risks / Trade-offs

- [余额来源容易被误解] → 列标题明确写“可用余额”，悬浮说明标注“上游余额按当前分组倍率折算的投影/管理员同步余额”；没有 managed projection 时显示“暂不可用”。
- [overview 数据在刷新前可能过期] → 复用页面现有 10 秒轮询和打开弹窗前的最新内存状态，不在渲染函数中自行缓存或发请求。
- [弹窗列数增加导致窄屏拥挤] → 使用移动端堆叠布局和不换行的数字样式，仅对账号名称和状态原因允许换行。

## Migration Plan

无需数据迁移。发布侧车静态资源后，旧 overview 响应仍可工作：字段缺失时前端按“未计算/暂不可用”降级显示。回滚只需恢复侧车镜像或静态资源版本。
